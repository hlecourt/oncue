# A subtitle is a stored entity with an opaque id

Each subtitle file the guard knows gets a row in the database with an opaque id, its path, video, language, current version and state, and its current proposal and best version hang off that row; the API and URLs use the id, not the path. Review state, proposals bound to one file version, Bazarr replacements and history all need one thing to attach to, and paths in URLs leaked the server's folder layout into browser history, logs and screenshots. The id never replaces the path checks: every action still confines the path to the allowed folders and refuses symlinks.
